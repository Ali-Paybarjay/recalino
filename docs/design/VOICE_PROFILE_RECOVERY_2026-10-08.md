## ۳. طرح انتخابی

سه گزینهٔ brief سنجیده شد:

- **فقط calibration حساب** (۲۰ مثبت و ۲۰ منفی): امن است، ولی عملاً هرگز فعال نمی‌شود.
- **الگوی شخصی بدون ارزیابی**: بدون شاهد مستقل، عدد دلخواه است.
- **انتخاب شده:** سیاست نسخه‌دار برای هر مدل، با calibration مستقل روی دادهٔ دارای مجوز و holdout جدا، همراه دو مرجع مستقل هر حساب (نمونهٔ صدا و یک کلاس تأییدشده).

قواعد پذیرش خودکار (`packages/core/src/voc/policy.ts`):

1. نمونه و دست‌کم یک مرجع کلاسِ «added» از همان نسخهٔ مدل لازم است. سیاست ارزیابی‌شدهٔ همان نسخه باید `autoAccept` داشته باشد.
2. دست‌کم دو صدا voiceprint داشته باشند (شرط دو نامزد حفظ شده است). همهٔ صداهای دارای voiceprint رقیب حساب می‌شوند، حتی صدای کوتاه. فقط صدای اول باید ≥۲۰ ثانیه گفتار تمیز داشته باشد؛ در غیر این صورت دلیل `no_clear_match` است.
3. **توافق** = کمینهٔ شباهت به نمونه و میانگین شباهت به کلاس‌های تأییدشده. باید ≥ `acceptScore` باشد. میانگین‌گیری نمی‌تواند ضعف یکی از دو مرجع را پنهان کند.
4. فاصلهٔ توافق صدای اول با **بیشترین شباهت** هر صدای دیگر به هر یک از دو مرجع باید ≥ `minMargin` باشد.
5. اگر کاربر قبلاً صدایی با امتیاز نزدیک را «نه» گفته باشد، باز هم از او پرسیده می‌شود.
6. نتیجهٔ خودکار هرگز مرجع تازه نمی‌سازد و بازخورد مستقل حساب نمی‌شود.

calibration خود حساب (`calibrateVoiceAcceptance`، ۲۰ تأیید و ۲۰ رد) فقط وقتی به کار می‌رود که برای آن نسخهٔ مدل هیچ ورودی‌ای در `VOICE_ACCEPTANCE_POLICIES` نباشد. این همان رفتار قبلی است. اگر ورودی ارزیابی‌شده‌ای باشد، جای calibration حساب را می‌گیرد؛ پس ورودی با `autoAccept: false` همهٔ کلاس‌ها را دستی نگه می‌دارد و calibration حساب هم نمی‌تواند پذیرش خودکار کند (آزمون `reference.int.test.ts`).

### مرجع و تأیید نخست

با تأیید دستی، `voiceReferenceOutcome` یکی از این نتیجه‌ها را ثبت می‌کند:

| نتیجه | معنا |
|---|---|
| `added` | مرجع افزوده شد |
| `short` | کمتر از ۲۰ ثانیه گفتار تمیز |
| `expired` | پس از انقضای ۲۴ ساعتهٔ بردار موقت |
| `missing` | بدون بردار، مثلاً تحلیل متنی |
| `mismatch` | شباهت به نمونه کمتر از `referenceConsistency` |

- **mismatch** انتخاب کاربر را نگه می‌دارد، چون تصمیم دستی اوست، اما هرگز مرجع نمی‌شود. UI می‌گوید این صدا شبیه نمونه نیست و «This is not my voice» را پیشنهاد می‌کند. پس تأیید اشتباهِ صدای مدرس پروفایل را آلوده نمی‌کند. حتی اگر از بررسی سازگاری بگذرد، قاعدهٔ «توافق هر دو مرجع» مانع پذیرش خودکار او می‌شود (آزمون SAFETY-2).
- مرجعی که بعداً با کلاس‌های تازه‌تر، نمونهٔ جدید یا حذف جلسه کنار برود، در خواندن `retired` نشان داده می‌شود.

### ابطال اعتماد

`invalidateAutomaticVoice` همهٔ پذیرش‌های خودکار حساب را به «نیازمند تأیید» برمی‌گرداند (`voice_reference_revoked`). این کار در موارد زیر رخ می‌دهد:

- revoke، reject یا none روی کلاس verified (رفتار قبلی)
- **جایگزینی نمونه** (تازه): در این حالت مراجع کلاس دوباره با نمونهٔ جدید سنجیده می‌شوند و مراجع ناسازگار `mismatch` می‌شوند.
- **حذف جلسه یا منبعی که مرجع بوده** (تازه)

در دو حالت تازه، اگر پذیرش خودکاری باطل شود، خروجی‌های HTML حساب هم مثل revoke دستی کنار گذاشته می‌شوند، چون ممکن است اشتباه گفتاری منسوب به کاربر را نشان داده باشند. اگر پذیرش خودکاری نبوده باشد، خروجی‌ها دست نمی‌خورند (`voice-enrollment.int.test.ts` و `privacy-voice.int.test.ts`). نشانهٔ پوشش ناقص یا نمونه‌برداری‌شدهٔ صوت در دلیل تازه حفظ می‌شود (`voice_reference_revoked_sampled_audio`).

revoke کل داده همچنان همه‌چیز را پاک می‌کند و نسخهٔ پروفایل را بالا می‌برد. worker دیررس نمی‌تواند داده را برگرداند.

### state machine (مشتق، بدون جدول تازه)

| مرحله | منبع داده |
|---|---|
| consent off | `voc.profile.enabled=false` |
| sample recording / processing | سمت مرورگر، و `voc.enrollment_request` در حال اجرا |
| sample ready | `readiness.sample` (نمونهٔ همان نسخهٔ مدل) |
| first-class confirmation | `status=unverified` با `match_reason=no_reference` |
| reference ready | `readiness.references ≥ 1` |
| later match accepted | `verified` + `automatic` |
| later match needs review | `unverified` + `match_reason` |
| unavailable / failed | `status` همان‌طور که بود |

`readiness.automatic` یکی از `off`، `needs_sample`، `needs_class`، `unavailable` یا `ready` است. «Class verified» و «reference ready» جدا هستند. درصد اطمینان یا confidence نمایش داده نمی‌شود.

### بازیابی پخش (VOICE-AC-07، VOICE-AC-08)

وضعیت‌های پخش از هم جدا شده‌اند: `loading`، `playable`، `missing`، `incomplete` و `unreadable`. خطای پخش هر کلیپ جدا گزارش می‌شود.

دستور «Listen» فقط وقتی نمایش داده می‌شود که کلیپ زمان‌دار وجود داشته باشد و صوت محلی قابل پخش باشد. اگر فقط متن هست، پیام روشن نمایش داده می‌شود.

**Select original recording** این مراحل را دارد:

1. اندازه با `size_bytes` ثبت‌شدهٔ سرور مقایسه می‌شود.
2. SHA-256 در worker و قابل لغو محاسبه می‌شود.
3. اگر نسخهٔ سالم از قبل هست، relink بی‌اثر و idempotent است.
4. در یک تراکنش IndexedDB قطعه‌ها در همان ردیف جایگزین می‌شوند. عکس‌ها و ثبت source حفظ می‌شوند. ضبط فعال، ردیف source دیگر و حساب حذف‌شده رد می‌شوند.
5. بایت‌ها بازخوانی و با checksum سرور مقایسه می‌شوند.
6. hook بدون reload دوباره خوانده می‌شود و URL قبلی revoke می‌شود.

نام فایل هرگز ملاک نیست. بدون checksum معتبر، relink انجام نمی‌شود.

listening excerptها از گفتار تمیز خودِ همان صدا ساخته می‌شوند: ≥۳ ثانیه، دور از صدای دیگر، بی‌متن، و فقط برای شنیدن. این برش‌ها شاهد اشتباه گفتاری نیستند. هیچ کلیپ یا صوتی روی سرور ساخته یا نگه داشته نمی‌شود (D29).

## ۷. انتشار و بازگشت

ترتیب پیشنهادی، هر مرحله با اجازهٔ صریح مالک محصول:

1. بازبینی و merge شاخه.
2. اعمال migration `20261008170203_voice_reference_outcome.sql` روی پروژهٔ ابری با `supabase db push`. این migration فقط افزایشی است: دو ستون nullable و یک check، بدون backfill.
3. deploy. پس از آن بررسی‌های تازه با pipeline جدید اجرا می‌شوند. تحلیل‌های قبلی دست نمی‌خورند.
4. پذیرش خودکار فقط با افزودن ورودی ارزیابی‌شده به `VOICE_ACCEPTANCE_POLICIES` روشن می‌شود، آن هم فقط اگر دروازه‌ها قبول شده باشند و مالک محصول تأیید کند. رفتار پیش‌فرض، بدون ورودی، همان رفتار فعلی است.

بازگشت:

- حذف ورودی سیاست، پذیرش خودکار تازه را فوراً خاموش می‌کند. پذیرش‌های قبلی تا تأیید یا رد کاربر می‌مانند.
- revert کد امن است: کد قبلی ستون‌های تازه را نمی‌خواند، پس migration می‌تواند بماند.
- برای بازگشت فقط pipeline، سه ثابت در `voice-engine.ts` و `voice-source-windows.ts` به مقدار قبلی برمی‌گردند. ورودی سیاست برای pipeline جدید ارزیابی شده و در آن حالت باید حذف شود.
- برگرداندن migration (حذف دو ستون) فقط با اجازهٔ جداگانه انجام شود.
