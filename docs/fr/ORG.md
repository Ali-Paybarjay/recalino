## هدف و مرز

ORG ساختار آموزشی کاربر را نگه می‌دارد: Course، Unit اختیاری و ClassSession (D13). تجربه اصلی ساده است: کاربر با New Class جلسه می‌سازد و لازم نیست پیش از آن دوره یا واحدی بسازد (AC-01).

یک کلاس واقعی همیشه یک ClassSession است، هر قدر هم طولانی باشد (PRD-CORE-02). ORG مالک tombstone جلسه است؛ پاک‌سازی فیزیکی را PRIV هماهنگ می‌کند.

**خارج از ORG:**

- منابع جلسه و رابطه SourceAsset با جلسه ← `SRC` (PRD-DATA-01)
- ضبط ← `REC`
- وضعیت پردازش ← `PROC`؛ ORG فقط وضعیت نمایشی مشتق را نشان می‌دهد
- پاک‌سازی فیزیکی داده جلسه و چرخه Backup ← `PRIV`
- اشتراک‌گذاری جلسه یا دوره و Teacher Mode ← خارج از MVP (D20، D21)

### FR-ORG-001 — ایجاد جلسه با New Class

- **ارجاع:** D13، AC-01، PRD بخش ۷ (گام ۲)، PRD-PROC-03
- **مبنا:** قطعی (D13)
- **اولویت:** P0
- **مرحله تحویل:** ۱
- **نقش مجاز:** learner
- **پیش‌شرط:** کاربر وارد شده، اعلام ۱۸+ و Learning Profile فعال دارد (FR-ACC-001، FR-ACC-003).
- **جریان اصلی:**
  1. کاربر New Class را انتخاب می‌کند. این دکمه از صفحه اصلی و صفحه هر دوره در دسترس است.
  2. فیلدها:
     - عنوان جلسه: اختیاری
     - تاریخ جلسه: پیش‌فرض امروز در timezone کاربر (FR-ACC-006)
     - دوره: اختیاری؛ اگر New Class از صفحه یک دوره زده شود، همان دوره از پیش انتخاب شده است
     - واحد: اختیاری، و فقط وقتی دوره انتخاب شده باشد
  3. اگر دوره‌ای انتخاب نشود، جلسه به دوره پیش‌فرض کاربر وصل می‌شود؛ اگر دوره پیش‌فرض وجود نداشته باشد، ساخته می‌شود (FR-ORG-002).
  4. کاربر به صفحه جلسه هدایت می‌شود تا ضبط یا آپلود را شروع کند.
- **حالت‌های خالی / بارگذاری / خطا:**
  - بدون دوره: توضیح کوتاه «جلسه در دوره پیش‌فرض قرار می‌گیرد».
  - هنگام ارسال: دکمه تأیید غیرفعال است.
  - خطای شبکه: پیام قابل فهم و امکان تلاش دوباره، بدون ساخت جلسه دوم.
- **ورودی و اعتبارسنجی:**
  - سقف طول عنوان طبق قرارداد API؛ متن راست‌به‌چپ و CJK درست نمایش داده می‌شود (FR-PLT-011).
  - تاریخ یک تاریخ تقویمی معتبر است، بدون ساعت. تاریخ گذشته و آینده هر دو مجازند، چون کاربر ممکن است کلاس دیروز را امروز آپلود کند یا جلسه را پیش از کلاس بسازد.
  - دوره و واحد باید متعلق به همین کاربر باشند و واحد باید متعلق به همان دوره باشد.
- **تغییر وضعیت:** ایجاد ClassSession، و در صورت نیاز Course پیش‌فرض. هیچ ProcessingRun یا منبعی ساخته نمی‌شود.
- **خروجی:** شناسه جلسه و هدایت به صفحه آن.
- **مجوز دسترسی:** فقط مالک. ارجاع به دوره یا واحد کاربر دیگر پاسخ «یافت نشد» می‌گیرد و وجود آن را افشا نمی‌کند (FR-PLT-002).
- **مصرف / سهمیه:** ندارد. ساختن جلسه با سهمیه صفر هم ممکن است.
- **Idempotency:** درخواست کلید idempotency دارد (FR-PLT-004). ارسال دوباره همان کلید، همان جلسه را برمی‌گرداند.
- **معیار پذیرش:**
  - Given کاربری بدون هیچ دوره، When New Class را بدون انتخاب دوره تأیید کند، Then یک جلسه در دوره پیش‌فرض ساخته می‌شود و Unit خالی می‌ماند (AC-01).
  - Given کاربری که دوره پیش‌فرض دارد، When جلسه دیگری بدون انتخاب دوره بسازد، Then جلسه به همان دوره پیش‌فرض وصل می‌شود و دوره پیش‌فرض دوم ساخته نمی‌شود.
  - Given یک درخواست ایجاد با کلید idempotency، When همان درخواست دوباره ارسال شود، Then همان جلسه برگردانده می‌شود و تعداد جلسات تغییر نمی‌کند.
  - Given شناسه دوره‌ای متعلق به کاربر دیگر، When در درخواست ایجاد استفاده شود، Then پاسخ «یافت نشد» است و هیچ جلسه‌ای ساخته نمی‌شود.
  - Given واحدی از دوره‌ای دیگر، When همراه دوره انتخاب‌شده ارسال شود، Then پاسخ `validation_failed` است.

### FR-ORG-002 — مدیریت دوره و دوره پیش‌فرض

- **ارجاع:** D13، AC-01، PRD بخش ۴.۱ (ساختار محتوا)
- **مبنا:** قطعی (D13)؛ نام دوره پیش‌فرض و قاعده حذف: قاعده پیشنهادی این سند
- **اولویت:** P0
- **مرحله تحویل:** ۱
- **نقش مجاز:** learner
- **پیش‌شرط:** Learning Profile فعال
- **جریان اصلی:**
  1. کاربر دوره می‌سازد (نام اجباری) و نام آن را تغییر می‌دهد.
  2. **دوره پیش‌فرض:** هر کاربر حداکثر یک دوره پیش‌فرض دارد. این دوره اولین بار با New Class بدون دوره ساخته می‌شود و نام پیشنهادی «My classes» دارد. یک دوره عادی است و قابل تغییر نام است.
  3. **حذف دوره فقط وقتی خالی است:** دوره‌ای که جلسه دارد حذف نمی‌شود. پیام می‌گوید اول جلسه‌ها را جابه‌جا (FR-ORG-004) یا حذف (FR-ORG-007) کنید. واحدهای خالی همراه دوره حذف می‌شوند.
  4. اگر دوره پیش‌فرض خالی حذف شود، New Class بعدی بدون دوره، دوباره دوره پیش‌فرض می‌سازد.
- **حالت‌های خالی / بارگذاری / خطا:** نام تکراری ← پیام روشن.
- **ورودی و اعتبارسنجی:**
  - نام دوره اجباری است و سقف طولش طبق قرارداد API است.
  - **پیشنهاد:** نام دوره در میان دوره‌های همان کاربر یکتاست، بدون حساسیت به حروف بزرگ و کوچک، تا انتخاب دوره در فرم‌ها مبهم نشود.
- **تغییر وضعیت:** ایجاد، تغییر نام یا حذف Course.
- **خروجی:** —
- **مجوز دسترسی:** فقط مالک (FR-PLT-002).
- **مصرف / سهمیه:** ندارد.
- **Idempotency:** ایجاد با کلید idempotency (FR-PLT-004). حذف دوباره همان دوره اثر دوباره ندارد.
- **معیار پذیرش:**
  - Given دوره‌ای با یک جلسه، When کاربر حذف آن را بخواهد، Then دوره حذف نمی‌شود و پیام راهنما نمایش داده می‌شود.
  - Given دوره‌ای خالی با دو واحد خالی، When حذف شود، Then دوره و هر دو واحد حذف می‌شوند.
  - Given دو درخواست هم‌زمان New Class بدون دوره برای کاربر تازه، When هر دو کامل شوند، Then فقط یک دوره پیش‌فرض وجود دارد و هر دو جلسه در آن هستند.
  - Given نام دوره‌ای موجود با حروف متفاوت، When دوره تازه با آن نام ساخته شود، Then پاسخ `validation_failed` است.

### FR-ORG-003 — واحد اختیاری

- **ارجاع:** D13، PRD بخش ۷ (گام ۲)
- **مبنا:** قطعی (D13: Unit اختیاری است و ساخت واحد صوری لازم نیست)
- **اولویت:** P1
- **مرحله تحویل:** ۱
- **نقش مجاز:** learner
- **پیش‌شرط:** دوره متعلق به کاربر
- **جریان اصلی:**
  1. کاربر داخل یک دوره واحد می‌سازد، نامش را تغییر می‌دهد و ترتیب واحدها را تعیین می‌کند.
  2. هر جلسه یا بدون واحد است، یا به یک واحد از همان دوره تعلق دارد.
  3. واحد فقط وقتی خالی است حذف می‌شود. راه دیگر، انتقال جلسه‌هایش به «بدون واحد» پیش از حذف است.
  4. جلسه‌های بدون واحد در فهرست دوره جدا و بدون عنوان صوری نمایش داده می‌شوند.
- **حالت‌های خالی / بارگذاری / خطا:** دوره بدون واحد: هیچ اشاره‌ای به واحد در صفحه دوره نیست، جز گزینه «افزودن واحد».
- **ورودی و اعتبارسنجی:** نام اجباری؛ یکتا داخل همان دوره (پیشنهادی، مانند FR-ORG-002).
- **تغییر وضعیت:** ایجاد، تغییر نام، ترتیب یا حذف Unit.
- **خروجی:** —
- **مجوز دسترسی:** فقط مالک.
- **مصرف / سهمیه:** ندارد.
- **Idempotency:** ایجاد با کلید idempotency.
- **معیار پذیرش:**
  - Given دوره‌ای بدون واحد، When صفحه دوره نمایش داده شود، Then جلسه‌ها مستقیم فهرست می‌شوند و هیچ واحد پیش‌فرضی ساخته نشده است.
  - Given واحدی با جلسه، When حذف درخواست شود، Then حذف نمی‌شود و پیام راهنما نمایش داده می‌شود.

### FR-ORG-004 — ویرایش و جابه‌جایی جلسه

- **ارجاع:** D13، PRD بخش ۷ (گام ۳)، PRD-CORE-05
- **مبنا:** قطعی
- **اولویت:** P1
- **مرحله تحویل:** ۱
- **نقش مجاز:** learner
- **پیش‌شرط:** جلسه متعلق به کاربر و حذف‌نشده
- **جریان اصلی:**
  1. کاربر عنوان و تاریخ جلسه را تغییر می‌دهد، از جمله پیش از پردازش (PRD بخش ۷، گام ۳).
  2. کاربر جلسه را به دوره یا واحد دیگری از خودش منتقل می‌کند. جابه‌جایی هیچ منبع، جزوه، کارت یا تاریخچه مروری را تغییر نمی‌دهد.
  3. جلسه بدون عنوان، عنوان نمایشی مشتق از تاریخ دارد، مثلاً «Class — 30 Sep 2026». این عنوان ذخیره نمی‌شود.
- **حالت‌های خالی / بارگذاری / خطا:** —
- **ورودی و اعتبارسنجی:** مانند FR-ORG-001.
- **تغییر وضعیت:** عنوان، تاریخ، دوره یا واحد جلسه.
- **خروجی:** —
- **مجوز دسترسی:** فقط مالک. مقصد باید متعلق به همین کاربر باشد.
- **مصرف / سهمیه:** ندارد.
- **Idempotency:** ارسال دوباره همان تغییر، نتیجه را عوض نمی‌کند.
- **معیار پذیرش:**
  - Given جلسه‌ای با جزوه و کارت، When به دوره دیگری منتقل شود، Then جزوه، کارت‌ها و تاریخچه مرور بدون تغییر در دسترس‌اند.
  - Given دوره مقصد متعلق به کاربر دیگر، When انتقال درخواست شود، Then پاسخ «یافت نشد» است و جلسه جابه‌جا نمی‌شود.
  - Given جلسه‌ای بدون عنوان، When در فهرست نمایش داده شود، Then عنوان مشتق از تاریخ دیده می‌شود.

### FR-ORG-005 — فهرست دوره‌ها و جلسه‌ها با وضعیت مشتق

- **ارجاع:** D13، PRD بخش ۱۱ (جدول وضعیت‌ها)، PRD-CORE-02
- **مبنا:** قطعی
- **اولویت:** P0
- **مرحله تحویل:** ۱ (وضعیت‌های ضبط و پردازش همراه REC و PROC در مرحله ۲)
- **نقش مجاز:** learner
- **پیش‌شرط:** —
- **جریان اصلی:**
  1. صفحه اصلی جلسه‌های اخیر را به ترتیب تاریخ جلسه نشان می‌دهد و دکمه New Class همیشه در دسترس است.
  2. صفحه هر دوره جلسه‌هایش را، به تفکیک واحد و به ترتیب تاریخ، نشان می‌دهد.
  3. هر جلسه یک **وضعیت نمایشی** دارد که از وضعیت‌های جداگانه ضبط (REC)، آپلود (SRC)، Run (PROC) و انتشار مشتق می‌شود. ORG ستون وضعیت مستقلی ذخیره نمی‌کند (PRD بخش ۱۱). نگاشت دقیق در FR ماژول PROC است.
  4. در مرحله ۱، پیش از وجود REC و PROC، وضعیت نمایشی فقط «بدون منبع» یا «منبع دارد» است.
- **حالت‌های خالی / بارگذاری / خطا:**
  - کاربر بدون جلسه: توضیح کوتاه و دکمه New Class، بدون صفحه یا بخش خالی برای امکانات خارج از MVP (PRD-CORE-06).
  - فهرست طولانی: صفحه‌بندی.
- **ورودی و اعتبارسنجی:** —
- **تغییر وضعیت:** —
- **خروجی:** —
- **مجوز دسترسی:** فقط جلسه‌ها و دوره‌های خود کاربر. جلسه حذف‌شده در هیچ فهرستی نیست (FR-ORG-007).
- **مصرف / سهمیه:** ندارد.
- **Idempotency:** —
- **معیار پذیرش:**
  - Given دو کاربر با جلسه، When هرکدام صفحه اصلی را باز کند، Then فقط جلسه‌های خودش را می‌بیند.
  - Given کاربر تازه، When صفحه اصلی باز شود، Then فقط توضیح و دکمه New Class نمایش داده می‌شود.
  - Given دوره‌ای با واحد و جلسه بدون واحد، When صفحه دوره باز شود، Then جلسه‌ها به تفکیک واحد و «بدون واحد» نمایش داده می‌شوند.

- **حالت‌های خالی / بارگذاری / خطا:** —
- **ورودی و اعتبارسنجی:** —
- **تغییر وضعیت:** —
- **خروجی:** —
- **مجوز دسترسی:** —
- **مصرف / سهمیه:** —
- **Idempotency:** —
- **معیار پذیرش:**
  - Given ضبط ۱۸۰ دقیقه‌ای، When پردازش با دو Part کامل شود، Then دقیقاً یک ClassSession وجود دارد و هیچ دوره یا واحد تازه‌ای ساخته نشده است (PRD-SEG-02).
  - Given Retry یک Part ناموفق، When کامل شود، Then تعداد جلسه‌ها تغییر نکرده است.

### FR-ORG-007 — حذف جلسه و tombstone

- **ارجاع:** PRD-PROC-05، AC-17، PRD-DEL-02، PRD-DEL-03، PRD-DEL-04، PRD-DEL-05، PRD-DATA-05، D29
- **مبنا:** قطعی
- **اولویت:** P0
- **مرحله تحویل:** ۱ (tombstone)؛ پاک‌سازی فیزیکی کامل در PRIV، مرحله ۵
- **نقش مجاز:** learner
- **پیش‌شرط:** جلسه متعلق به کاربر
- **جریان اصلی:**
  1. کاربر «حذف کامل جلسه» را انتخاب می‌کند. تأییدیه صریح می‌گوید:
     - جزوه و فایل‌های سرور این جلسه، و کارت‌هایی که فقط از همین جلسه آمده‌اند همراه تاریخچه مرورشان، حذف می‌شوند.
     - کارت یا منبعی که به جلسه یا منبع دیگری هم وابسته است، طبق محاسبه وابستگی بررسی می‌شود (PRD-DATA-02، PRD-DEL-03).
     - فایل‌هایی که قبلاً دانلود شده‌اند (HTML، APKG یا کپی صوت) قابل پس‌گرفتن نیستند (PRD-DEL-05).
  2. پس از تأیید، در **یک تراکنش**:
     - جلسه tombstone می‌گیرد: زمان حذف و شناسه درخواست حذف.
     - همه Runهای باز جلسه سیگنال لغو می‌گیرند (PROC).
     - یک DeletionRequest برای پاک‌سازی ثبت می‌شود.
  3. از همین لحظه جلسه از همه فهرست‌ها و APIها حذف است و پاسخ «یافت نشد» می‌گیرد. هیچ پردازش، ویرایش یا Export تازه‌ای برایش ممکن نیست.
  4. PROC پیش از انتشار هر نتیجه، tombstone را در همان تراکنش انتشار بررسی می‌کند و نتیجه دیررس را منتشر نمی‌کند (PRD-PROC-05، AC-17).
  5. پاک‌سازی فیزیکی داده‌های وابسته را PRIV هماهنگ می‌کند (PRD-DEL-03). هدف پیشنهادی: حداکثر ۲۴ ساعت در سامانه فعال (PRD-DEL-04). تا ساخت PRIV، tombstone به‌تنهایی مانع هر دسترسی و احیا است.
  6. نسخه محلی صوت روی دستگاه طبق FR ماژول REC پاک می‌شود. روی دستگاه غیرمتصل، در اولین دسترسی ممکن (PRD-DEL-05).
  7. حذف فقط فایل خام با حفظ محتوای مشتق (PRD-DEL-02) در ORG نیست. برای صوت کلاس این رفتار خودکار است (D29) و برای منابع دیگر در SRC و PRIV تعریف می‌شود.
- **حالت‌های خالی / بارگذاری / خطا:** وضعیت پاک‌سازی از مسیر درخواست حذف قابل پیگیری است (AC-17)؛ نمایش آن در PRIV.
- **ورودی و اعتبارسنجی:** —
- **تغییر وضعیت:** tombstone جلسه؛ DeletionRequest؛ سیگنال لغو Runها. **در MVP بازگرداندن جلسه حذف‌شده وجود ندارد (پیشنهادی).**
- **خروجی:** شناسه درخواست حذف.
- **مجوز دسترسی:** فقط مالک.
- **مصرف / سهمیه:** رزروهای باز طبق FR-QUOTA-006 آزاد می‌شوند.
- **Idempotency:** حذف دوباره همان جلسه، همان DeletionRequest را برمی‌گرداند و tombstone تازه نمی‌سازد.
- **معیار پذیرش:**
  - Given جلسه‌ای در حال پردازش، When کاربر آن را حذف کند و Worker بعداً نتیجه را آماده کند، Then نتیجه منتشر نمی‌شود و جلسه احیا نمی‌شود (AC-17).
  - Given جلسه حذف‌شده، When شناسه‌اش در هر API استفاده شود، Then پاسخ «یافت نشد» است.
  - Given درخواست حذف، When دو بار ارسال شود، Then یک tombstone و یک DeletionRequest وجود دارد.
  - Given جلسه حذف‌شده، When فهرست دوره نمایش داده شود، Then آن جلسه در فهرست نیست و دوره اگر جلسه دیگری ندارد قابل حذف است.
