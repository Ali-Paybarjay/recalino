# بلندگوی تلفظ کنار واژه در Recall و Class Notes

تاریخ: 2026-10-08. مبنا: درخواست صریح مالک محصول در همین گفت‌وگو؛ گسترش قابلیت D46. نقطهٔ شروع production بررسی‌شده `83e51f4cc2e30435a16ae691a6ddc1acb5a9bf30` است. این طرح مجوز انتشار عمومی یا تغییر تنظیم ابری ندارد.

## هدف و دامنه

در Recall، پس از نمایش جواب، دکمهٔ بلندگو کنار واژه/عبارت قابل‌تلفظ قرار می‌گیرد. در Class Notes نیز کنار واژه/عبارت هر مدخل معتبر دکمهٔ پخش وجود دارد. تولید فقط پس از کلیک و با سرویس Kokoro، صدای نسخه‌دار، کش خصوصی و سهمیهٔ موجود است. هیچ تماس AI هنگام بازکردن صفحه یا برای تمام کلمات انجام نمی‌شود. ثبت و شناسایی صدای شخص و معلم تطبیقی در دو بریف جدا به Claude Code سپرده می‌شوند؛ در این برنچ پیاده نمی‌شوند. مدل متن فعلی حفظ می‌شود؛ Haiku 5.5 تأیید کیفیت ندارد.

| قابلیت | مسئولیت | وابستگی |
|---|---|---|
| inline-recall-pronunciation | بلندگوی قابل دسترس کنار هدف آشکارشده، پخش/تلاش دوباره/توقف | card، media، ReviewView |
| note-pronunciation | هدف معتبر از نسخهٔ جاری جزوه، کنترل کنار مدخل، همان کش | note، lkm، media، ClassNotesFrame |
| claude-briefs | دو prompt مستقل برای تشخیص صدا و معلم تطبیقی | شواهد بررسی کد؛ بدون تغییر رفتار این دو قابلیت |

## تصمیم اجرا و مرز امنیت

- هدف از مدل ساخت‌یافته مشتق می‌شود. HTML کارت، متن فارسی، تعریف یا فریم مبهم به‌عنوان متن صوت حدس زده نمی‌شود. رفتار کارت قدیمیِ دارای مدل معتبر حفظ می‌شود.
- API جزوه روی مسیر موجود media درخواست `note_pronunciation` با `learningItemId` و `expectedNotebookRevisionId` می‌گیرد. سرور مالکیت کلاس/جزوه و نسخهٔ جاری را بررسی و متن را استخراج می‌کند. نسخهٔ stale خطای صریح می‌گیرد؛ صفحهٔ تاریخچهٔ read-only کنترل تازهٔ صوت ندارد.
- iframe جزوه origin مشترک نمی‌گیرد. پل ثابت و متعلق به برنامه، با nonce و CSP محدود، فقط درخواست ID مدخل و کانال همان frame را به parent می‌فرستد. script متن منابع/مدل اجرا نمی‌شود؛ `connect-src`, form و frame مسدود می‌مانند. parent فقط پیام همان `contentWindow`، کانال فعلی و ID واجد هدف را می‌پذیرد. لینک و صوت خصوصی در parent باقی می‌مانند.
- خروجی دانلود/HTML/Anki مستقل و پیش‌فرض renderer همان سند بدون کنترل تعاملی است. مجوز `allow-same-origin`، اجرای HTML/کد مدل، یا iframe عمومیِ مجاز به script اضافه نمی‌شود.
- دکمهٔ icon با نام قابل‌دسترسی، focus واضح، وضعیت loading/error/ready و ناحیهٔ لمس مناسب کار می‌کند. چند صوت هم‌زمان پخش نمی‌شوند؛ خروج، تغییر کارت/نسخه/هدف درخواست و پخش قبلی را لغو می‌کند.
- هیچ migration دیتابیس، dependency، سرویس پولی تازه یا تغییر سقف هزینه لازم نیست. unknown outcome و request key موجود حفظ می‌شوند؛ retry کور تولید پولی ندارد.

## معیارهای پذیرش

1. بلندگو در Recall قبل از Show answer هدف مخفی را افشا نمی‌کند؛ پس از آن کنار عنوان واژه قرار دارد. فریم جداشدنی نیز هدف درست صوت را حفظ می‌کند.
2. در Class Notesِ جاری، production و recognition دارای هدف معتبر کنترل کنار همان عنوان دارند؛ جزوهٔ قدیمی معتبر و مدخل بدون کارت نیز کار می‌کنند.
3. کلیک نخست یک درخواست برای هدف معتبر می‌سازد؛ replay از صوت آماده استفاده می‌کند. خطای پیکربندی/پخش واضح است و مطالعه را قفل نمی‌کند.
4. دسترسی حساب دیگر، کلاس دیگر، نسخهٔ stale، ID غایب، متن دلخواه/HTML و هدف نامعتبر پیش از dispatch رد می‌شوند.
5. پیام frame دیگر، کانال قدیمی، ID نادرست یا raw text درخواست صوت نمی‌سازد. محتوای شبیه script در عنوان/منبع همچنان متن است.
6. صفحهٔ تاریخچه، export و renderer مستقل script یا درخواست صوت تازه ندارند. theme و محتوای کامل جزوه حفظ می‌شوند.
7. مرورگر در 390 و 1440، صفحه‌کلید، RTL/LTR، loading، failure، replay، تغییر کارت و توقف صوت بررسی می‌شوند؛ داده و provider مصنوعی هستند.

## ترتیب و بررسی

API و helper خالص → کنترل مشترک صوت و Recall → پل محدود Class Notes → آزمون‌های واحد و مرورگر → verify/build/client scan → commit و نتیجهٔ قابل بازبینی. دو بریف مستقل نیز به نسخهٔ قابل دریافت در checkout اصلی کپی می‌شوند؛ تغییرهای باز و نامرتبط آن checkout دست‌نخورده‌اند.

Runtime: Node 24.19، pnpm 12.4.2. فرمان‌های نهایی: `pnpm verify`، `pnpm build`، `pnpm check:client-bundle`. integration فقط با دیتابیس محلی اختصاصی و URL صریح، بدون `.env` ابری یا reset stackهای دیگر. آزمون‌های UI با fixture مصنوعی، سرور مختص این worktree و پورت مستقل اجرا می‌شوند. خرید سرویس، cloud write، merge به main و deployment فقط در مرحلهٔ نهایی طبق بخش ۹ PROJECT_SPEC بررسی می‌شوند.
