# عنوان و موضوع‌های جلسه از مطالب آموزشی

مبنا: درخواست صریح مالک محصول، 2026-10-04؛ تصمیم D40، ادامهٔ D39.

## معیار پذیرش

- هر جلسه در کورس خودش و با تاریخ ثبت‌شده باقی می‌ماند؛ منابع، ضبط، جزوه و کارت‌ها همان شناسهٔ جلسه را دارند.
- وقتی نام سفارشی خالی است، نام نمایشی از عنوان جزوهٔ جاری و منتشرشده گرفته می‌شود؛ پیش از انتشار جزوه، عنوان آخرین مدل آموزشی معتبر و قابل دسترسی مبناست. تا آماده‌شدن مطالب، نام مبتنی بر تاریخ نمایش داده می‌شود.
- نام سفارشی کاربر اولویت دارد و با تولید یا ویرایش مطالب بازنویسی نمی‌شود. پاک‌کردن آن یا «Use automatic title» نام خودکار را برمی‌گرداند.
- موضوع‌های درس از همان محتوایی می‌آیند که عنوان خودکار را تعیین می‌کند. نمای کورس و کلاس‌ها خلاصهٔ موضوع‌ها، تاریخ و منشأ عنوان را نشان می‌دهد؛ صفحهٔ جلسه همهٔ موضوع‌ها را نشان می‌دهد.
- جلسه‌های کورس با ترتیب تاریخ روشن نمایش داده می‌شوند؛ مطالعهٔ پیوسته از قدیمی به جدید و فهرست جلسه‌ها از جدید به قدیم است. مطالب هر جلسه مستقل قابل بازکردن‌اند.
- جزوهٔ ویرایش‌شدهٔ منتشرشده بر پیشنهاد جدیدِ منتشرنشده مقدم است. محتوای حذف‌شده، کاربر دیگر، کورس دیگر یا مدل تولیدی مربوط به نسخهٔ قدیمی منابع وارد نمای جدید نمی‌شود.
- نسخهٔ نمونه نیز این رفتار را با metadata مصنوعی و نشان دائمی نمونه نمایش می‌دهد.

## معماری

عنوان و موضوع‌ها در مدل معتبر LKM و revision منتشرشدهٔ NOTE ذخیره شده‌اند. read model تازهٔ NOTE به نام `LearningSession` نام نمایشی و موضوع‌ها را از این داده‌ها استخراج می‌کند؛ title اصلی ORG فقط نام سفارشی است. تاریخ و مالکیت در ORG باقی می‌ماند. ذخیرهٔ تکراری عنوان، migration یا درخواست اضافی AI لازم نیست.

خواندن API و صفحه‌های Today، Classes، Course، Class و Course materials از همین read model استفاده می‌کنند. readها گروهی، فقط‌خواندنی و با کنترل مالکیت و tombstone اجرا می‌شوند؛ مرز ORG → NOTE/LKM ایجاد نمی‌شود. پاسخ ساخت و ویرایش، نتیجهٔ تراکنش ORG را مستقیم برمی‌گرداند؛ خواندن metadata بعد از commit نباید ذخیرهٔ موفق را خطا معرفی کند.

## اجرا و بررسی

- هسته: projection گروهی LKM/NOTE، عنوان و موضوع‌ها، آزمون اولویت انتشار/ویرایش/نام سفارشی/نسخهٔ منابع/مالکیت/حذف.
- وب: readهای یکسان در API و صفحات، راهنمای نام خودکار و بازگشت به آن، خلاصهٔ موضوع و تاریخ، نمای کامل موضوع‌های جلسه.
- نمونه و مرورگر: پردازش نمونه، نام خودکار، نام سفارشی، ترتیب زمان، چند کورس؛ مرورگر واقعی با دادهٔ آزمایشی محلی.
- TypeScript، Biome روی کد، مرزهای ماژول‌ها، آزمون‌های مرتبط و production build.

انتشار production و تغییر دادهٔ ابری نیازمند مجوز جدا هستند؛ لینک سایت برای بررسی داده شده است.

## وضعیت

پیاده‌سازی هسته، وب و نمونه و بررسی‌های مرتبط کامل‌اند. تغییری در دیتابیس ابری یا استقرار production انجام نشده است.

## نتیجهٔ پیاده‌سازی

- `LearningSession` در NOTE عنوان نمایشی، منشأ عنوان و موضوع‌های درس را گروهی می‌خواند. جزوهٔ جاری و ویرایش‌های منتشرشده مقدم‌اند؛ مدل جدیدِ منتشرنشده آن‌ها را عوض نمی‌کند. fallback تولیدی باید به نسخهٔ فعلی منابع مربوط باشد.
- خواندن API و همهٔ سرصفحه‌های جلسه، Today، فهرست کلاس‌ها، کورس و جریان مطالب از عنوان خودکار استفاده می‌کنند. تاریخ به صورت مستقل و خلاصهٔ سه موضوع در فهرست نمایش داده می‌شوند؛ لینک «See all topics» صفحهٔ جلسه با فهرست کامل موضوع‌ها را باز می‌کند.
- New Class نام سفارشی را اختیاری نگه می‌دارد و رفتار نام خودکار را توضیح می‌دهد. «Use automatic title» در تنظیمات کلاس، نام سفارشی را خالی می‌کند و پس از Save changes عنوان آموزشی نمایش داده می‌شود. انتشار جزوه و پایان پردازش صفحه را refresh می‌کنند.
- readهای فقط‌خواندنی snapshot دارند؛ enrichment ورودی قدیمی را دوباره با مالکیت از ORG می‌خواند. نام سفارشی، تاریخ، کورس و `updatedAt` با خواندن مطالب تغییر نمی‌کنند. ساخت و ویرایش نتیجهٔ تراکنش اصلی را مستقیم برمی‌گردانند تا خطای metadata پس از commit ذخیرهٔ موفق را خطا معرفی نکند.
- prompt تولید موجود، عنوان کوتاه و مشخص دربارهٔ مفاهیم واقعی درس و برچسب موضوع‌های مستند می‌خواهد؛ فراخوانی AI جدا اضافه نشده است. نمونه از metadata صریحِ محتوای مصنوعی استفاده می‌کند و عنوان‌های قدیمی ذخیره‌شده را حفظ می‌کند.
- migration یا ذخیرهٔ تکراری لازم نیست. استقرار یا نوشتن دیتابیس ابری برای این تغییر انجام نشده است.

## شواهد بررسی

- TypeScript کل مخزن، Biome روی `apps packages tools`، مرزهای ماژول‌ها و `git diff --check`: موفق.
- **۴۲۶ از ۴۲۶** آزمون واحد در ۵۶ فایل: موفق.
- **۱۸ از ۱۸** آزمون یکپارچهٔ هدفمند: هشت آزمون عنوان/مطالب کورس، پنج آزمون ORG و classSession، پنج آزمون classes و noteNotebook؛ اولویت انتشار، نام سفارشی، منابع قدیمی، مالکیت، انتقال و tombstone پوشش داده شدند. مجموعهٔ کامل یکپارچه در این مرحله تکرار نشد؛ محدودیت آزمون صوت قبلی در گزارش D39 ثبت شده است.
- **۱۳ سناریوی مرورگر واقعی** عنوان/کورس/مطالب: موفق در اجراهای نهایی. یک سناریوی فرم هنگام تغییر server دچار hot reload شد؛ اجرای دوبارهٔ همان سناریو و سناریوی نام خودکار پس از ثابت‌شدن کد هر دو موفق بودند.
- axe و نبود overflow در عرض‌های ۳۹۰ و ۱۴۴۰ برای صفحهٔ کلاس، کورس و مطالب کورس موفق‌اند. تصاویر بررسی‌شده: [جلسهٔ موبایل](../../artifacts/verification/session-learning/learning-session-mobile-class.png)، [مطالب دسکتاپ](../../artifacts/verification/session-learning/learning-session-desktop.png).
- production build، وابستگی‌های native و بررسی نبود secrets در خروجی قابل دریافت مرورگر: موفق.
- بازبینی مستقل: ایراد پاسخ پس از commit اصلاح شد؛ مورد قابل اقدام دیگری گزارش نشد.
- **۲۸ از ۲۸** سناریوی انتخاب‌شدهٔ مرورگر نمونه: موفق، شامل سه سناریوی تازهٔ D40 برای عنوان/موضوع، حفظ و پاک‌کردن نام سفارشی و دادهٔ قدیمی. فقط آزمون ساعت جعلی ضبط که کدش در این مرحله تغییر نکرده بود انتخاب نشد. اجرای نخست پیش از تعامل UI در محافظ محیط متوقف شد؛ متغیر محیطی اشتباه بود و با `RECALINO_UI_PREVIEW=1` اصلاح شد، محافظ آزمون تغییر نکرد. انتظار آماده‌شدن state در سناریوی legacy صریح شد و اجرای نهایی همان سناریو نیز موفق است.

بررسی لینک production با ابزار وب و HTTP در محیط اجرا در دسترس نبود؛ نتیجهٔ فوق به کد و آزمون‌های محلی مربوط است. این گزارش موفقیت استقرار آنلاین را ادعا نمی‌کند.
