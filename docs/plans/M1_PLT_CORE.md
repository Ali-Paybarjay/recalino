# برنامه M1 — هسته سمت سرور ماژول PLT

> **وضعیت:** تأییدشده توسط مالک محصول (2026-10-01)، همراه FR ماژول PLT — اجرا روی شاخه `feat/plt-core`؛ انجام‌شده، در انتظار تأیید ادغام  
> **تاریخ:** 2026-09-30 (تأیید: 2026-10-01)  
> **مبنا:** [FR ماژول PLT](../fr/PLT.md) · [PROJECT_SPEC](../PROJECT_SPEC.md) · [ADR-0001](../adr/0001-stack-and-hosting.md) · [ADR-0002](../adr/0002-data-access-and-migrations.md) · [گزارش M0](M0_REPO_SCAFFOLD.md)

## هدف

ساختن زیرساخت سمت سروری که همه ماژول‌های بعدی به آن تکیه دارند و بدون رابط کاربری یا سرویس ابری قابل آزمون است. **M1 هیچ صفحه یا قابلیت محصولی نمی‌سازد.**

## تصمیم‌های فنی داخل دامنه FR و spec

| مورد | انتخاب | دلیل |
|---|---|---|
| جدول‌های PLT | schema جدا به نام `plt` با جدول‌های `idempotency_key`، `rate_limit_bucket`، `security_event` و `audit_event`؛ RLS فعال و بدون policy؛ دسترسی فقط برای `recalino_app` | ADR-0002 |
| لاگ | **فهرست مجاز فیلدها، نه فهرست ممنوع:** فقط فیلدهای شناخته‌شده و بی‌خطر نوشته می‌شوند. خروجی JSON روی stdout، که Vercel ثبتش می‌کند | فیلد تازه‌ای که کسی فراموش کند پاک‌سازی شود، هرگز به لاگ نمی‌رسد (PRD-PRIV-06). سرویس لاگ تازه لازم نیست (D28). |
| کنترل نرخ | پنجره زمانی ثابت با شمارنده در Postgres | برای مقیاس پایلوت کافی است؛ سرویس تازه نمی‌خواهد |
| مقادیر فنی | در پیکربندی با مقدار پیش‌فرض پیشنهادی، طبق Q-PLT-2: نگهداری کلید idempotency ۲۴ ساعت، سقف‌های کنترل نرخ، و مرز روز مطالعه ساعت ۴ صبح به وقت کاربر (G07) | اعداد در کد نیستند و بدون تغییر کد عوض می‌شوند |
| رابط API | Route Handlerهای Next.js با یک wrapper مشترک برای `request_id`، قالب خطا، لاگ و idempotency | ADR-0001؛ منطق دامنه در `packages/core` می‌ماند |
| مسیر API در M1 | فقط `GET /api/health`، که عمومی است و داده‌ای برنمی‌گرداند | برای آزمون wrapper و پایش سلامت بعدی |

## کارها

همه کارها روی شاخه `feat/plt-core` انجام می‌شوند، مثل M0. پس از سبز شدن CI، pull request برای تأیید شما باز می‌شود.

- [x] **T1 — schema به نام `plt` و مرز نام schema**
  - **پذیرش:**
    - migration، schema `plt` را با دسترسی فقط برای `recalino_app` می‌سازد.
    - نقش‌های مرورگر (`anon` و `authenticated`) به آن دسترسی ندارند.
    - آزمون مرز ثابت می‌کند نام schema هر ماژول فقط در پوشه همان ماژول آمده است (ADR-0002، قاعده ۴).
  - **بررسی:** `pnpm db:reset && pnpm db:types && pnpm verify`
- [x] **T2 — قالب خطا و wrapper مسیرهای API (FR-PLT-003)**
  - **پذیرش:** همه معیارهای پذیرش FR-PLT-003، از جمله آزمون قرارداد پاکت خطا. خطای پیش‌بینی‌نشده فقط `request_id` برمی‌گرداند.
  - **بررسی:** آزمون واحد و یکپارچه
- [x] **T3 — لاگ امن، رخداد امنیتی و AuditEvent (FR-PLT-007)**
  - **پذیرش:** همه معیارهای پذیرش FR-PLT-007. آزمون canary ثابت می‌کند متن نشانه‌دار کلاس در هیچ لاگی نیست.
  - **بررسی:** آزمون واحد و یکپارچه
- [x] **T4 — نگهداری اسرار (FR-PLT-009)**
  - **پذیرش:**
    - ماژول‌های سمت سرور با `server-only` محافظت می‌شوند.
    - CI بسته کلاینت را برای نام متغیرهای محرمانه و الگوهای کلید جست‌وجو می‌کند و در صورت یافتن، شکست می‌خورد.
    - آزمونی ثابت می‌کند این بررسی یک کلید کاشته‌شده را پیدا می‌کند.
  - **بررسی:** `pnpm build` و مرحله تازه CI
- [x] **T5 — Idempotency (FR-PLT-004)**

  - **بررسی:** آزمون یکپارچه

### تصمیم‌های پیاده‌سازی

- **idempotency بدون وضعیت «در حال اجرا»:** ردیف کلید و اثر درخواست در یک تراکنش ثبت می‌شوند. درخواست هم‌زمان با همان کلید تا پایان اولی منتظر می‌ماند و همان پاسخ را می‌گیرد. اگر اولی برگشت بخورد، دومی اجرا می‌شود.
- **لاگ با فهرست مجاز:** فقط فیلدهای شناخته‌شده نوشته می‌شوند و هر مقدار متنی که شکل شناسه نداشته باشد `[redacted]` می‌شود. برای خطای پیش‌بینی‌نشده فقط نام خطا و کد Postgres ثبت می‌شود، نه پیام آن.
- **کنترل نرخ با IP:** فقط hash کلیددار IP ذخیره می‌شود و کلیدش متغیر محیطی `RATE_LIMIT_IP_KEY` است.
- **قاعده ۴ ADR-0002 فقط کد اصلی را می‌سنجد.** فایل‌های آزمون برای دیدن اثر کار می‌توانند جدول هر ماژول را بخوانند.
- **شکست در ثبت رخداد امنیتی** پاسخ درخواست را خراب نمی‌کند و خودش لاگ می‌شود.

### محدودیت‌ها و کارهای باقی‌مانده

- **FR-PLT-001 (نشست):** تا M2 هیچ کاربری نشست ندارد و همه مسیرهای کاربری `unauthenticated` می‌گیرند.
- **FR-PLT-005 (صف):** پاک‌سازی کلیدهای منقضی idempotency و شمارنده‌های کنترل نرخ به‌صورت تابع ساخته شده، ولی زمان‌بندی‌اش همراه صف در M2 می‌آید.
- **معیار «Job دست‌کاری‌شده» در FR-PLT-002** همراه صف در M2 آزموده می‌شود.
- **FR-PLT-008 و 014** (لینک امضاشده و لایه ذخیره‌سازی) با SPIKE-05 و ماژول SRC ساخته می‌شوند. **FR-PLT-010 تا 012** با پایه UI.
- **مقدارهای پیشنهادی** (کنترل نرخ، نگهداری کلید، مرز روز ساعت ۴) تا پاسخ Q-PLT-2 و دروازه G07 پیشنهادی می‌مانند.
- **رخدادهای امنیتی و Audit** هنوز سیاست نگهداری ندارند؛ تعیین آن با ماژول PRIV است.
