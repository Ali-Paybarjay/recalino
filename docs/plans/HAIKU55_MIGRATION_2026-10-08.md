# مهاجرت تولید دانش به Haiku 5.5 — 2026-10-08

وضعیت: پیاده‌سازی با اجازهٔ صریح مالک محصول برای انجام کارهای لازم تا پایان. مرجع تصمیم انتخاب مدل D36 و دامنهٔ تدریس/Recall در D46 است. این تغییر، قرارداد نهایی LKM نسخهٔ ۱، امکانات محصول و سهمیه‌های مصوب را عوض نمی‌کند.

## هدف و شواهد

آزمون قبلیِ ۲۰ اجرا در هشت درس و دو تکرار، برای هر دو مدل ۶ خروجی معتبر از ۱۰ داشت. خروجی‌های معتبر 5.5 میانگین کیفیت ۳٫۸ از ۴ و هزینهٔ مجموعه ۸۷٫۳٪ کمتر داشتند. چهار شکست آن ناشی از نبودن `classNotes.board`، نبودن `study.sourceFa`، جابه‌جایی `sourceClassifications` و شکست خروجیِ اصلاحی بود. صرف تعویض ID مدل برای فعال‌سازی کافی نیست.

این‌ها تغییر در ماژول‌های موجودند؛ ماژول محصول یا عامل اجرایی جدید ساخته نمی‌شود. ترتیب کار: قرارداد provider و DTO به‌صورت موازی، اتصال worker، آزمون‌های واحد و یکپارچه، ارزیابی واقعی، بررسی انتشار.

## قرارداد فنی

- مدل فقط محتوای آموزش، سؤال‌ها و کلیدهای محدود شواهد را تولید می‌کند. UUID، locator، نوع مدرک، creation، زبان، تاریخ، زمینهٔ جلسه، وضعیت استخراج، برچسب منشأ و قسمت‌های خالیِ قطعی روی سرور ساخته می‌شوند.
- قواعد و معانی آموزشی با مقدار پیش‌فرض یا حذف محتوا اصلاح نمی‌شوند. هر ادعا کلیدهای واقعیِ همهٔ شواهد ضروری را دارد؛ مثال‌های تازه از مطالب کلاس متمایز می‌مانند. کلید ناموجود، انتساب ساختگی یا کارت نامعتبر رد می‌شود.
- grammar و lexical در DTO از هم قابل تشخیص‌اند تا enum و فیلدهای سؤال اشتباه نشوند. سؤال و پاسخ کامل با هم اعتبارسنجی می‌شوند؛ پاسخ واژگانی در صورت سؤال افشا نمی‌شود.
- محدودیت محتوا 6144 باقی می‌ماند. override دقیق `anthropic/claude-haiku-5.5` سقف فیزیکی 12000 و effort کم دارد. snapshotهای قدیمی بدون override همان رفتار سابق را دارند. بازگشت به 4.5، تنظیم 5.5 را روی آن اعمال نمی‌کند.
- مدل vision فعلی، STT و TTS با این مهاجرت متنی تغییر نمی‌کنند؛ ارتقای vision نیاز به ارزیابی مستقل دارد.
- schema نهایی، قواعد ownership/evidence/language/study و رندر مورد اعتماد حفظ می‌شوند. پاسخ خام مدل مستقیماً رندر یا اجرا نمی‌شود.
- canonical KnowledgeModel پس از decode و با حفظ accounting، قبل از checkpoint ذخیره می‌شود. شکست decode بعد از پرداخت باید هزینهٔ واقعی را ثبت کند. خروجی/معنای checkpoint قبلی بی‌اجازه بازنویسی نمی‌شود.
- اصلاح‌ها، قطع خروجی، retry، unknown outcome و سقف هزینه همان قواعد محدود و idempotent فعلی را حفظ می‌کنند. تغییر مدل/نسخه مانع reuse نامعتبر می‌شود.
- تولید خطای گفتاری و اثبات هویت صوت از DTO مجاز نیست و همچنان projection سرور است. نقش user_notes یا نام یک شخص به‌تنهایی اثبات نویسندگیِ کاربر نیست. قواعد نمونه‌های چاپی/خطاهای تأییدنشده محافظه‌کارانه می‌مانند.

## معیار پایان

1. آزمون‌های provider، DTO و worker، snapshot قدیمی، بازگشت به 4.5، مالکیت شواهد، قطع پاسخ، accounting شکست، cache و اصلاح محدود را پوشش دهند.
2. `pnpm verify` و build مربوط عبور کنند؛ شبکهٔ AI در آزمون‌های معمول و CI mock بماند.
3. ارزیابی opt-in با دادهٔ مصنوعی روی ۱۰ اجرای قبلی و ۴ درس تازه: ۱۴/۱۴ قبولی نهایی، دست‌کم ۱۳/۱۴ در تلاش اول، بدون خطای مهم آموزش/منشأ/دستور جعلی، پوشش کافی و کیفیت حداقل ۳ از ۴. transport منتخبِ نسخه‌دار مستقیم JSON است؛ اعتبارسنجی strict محلیِ DTO و LKM باید عبور کند. حالت native یا تضمین کامپایل remote ادعا نمی‌شود.
4. هیچ شکست با coercion enum، حدس هویت یا ارجاع، یا پاک‌کردن محتوای واقعی پنهان نشود. هزینه و زمان شامل اصلاح‌ها و شکست‌ها ثبت شوند.
5. فایل‌ها در برنچ `codex/haiku55-migration` و worktree مستقل باشند؛ تغییرهای هم‌زمان checkout اصلی حفظ شوند. هیچ وابستگی یا migration دیتابیس تازه لازم نیست.

## اجرا و مرزها

### بازنگری فنی transport پس از شواهد واقعی

هدف اولیهٔ کامپایل native یک ترجیح فنی در این طرح بود، نه درخواست مستقل مالک محصول. سه DTO متفاوت با حدود اختیاری/union مجاز، روی مسیر واقعیِ دارای ZDR با `compiled grammar is too large` رد شدند. یک schema کوچک روی همان مسیر موفق بود؛ انتخاب مستقیم Anthropic یا Azure، با حفظ ZDR، به پاسخ معلومِ نبودن endpoint واجد شرایط رسید. این شواهد در `artifacts/verification/haiku55-migration*` و `haiku55-native-diagnostics` محفوظ‌اند؛ درس‌های تازه هنوز در این تلاش‌ها اجرا نشده بودند.

برای حفظ اولویت هزینه و اطمینان‌پذیری، فقط override مدل 5.5، `structuredOutputMode=json_object` می‌گیرد و از transport JSON موجود استفاده می‌کند. کامپایل و HTTP ناموفقِ اولیه حذف می‌شوند؛ تعداد generation افزایش نمی‌یابد. این انتخاب، هیچ بررسی Zod، LKM، evidence، ownership، زبان، سؤال/پاسخ، حسابداری یا معیار کیفیت را کاهش نمی‌دهد. همان پاسخ خام قبل از ذخیره/انتشار اعتبارسنجی می‌شود؛ metadata قطعی از مدل پذیرفته نمی‌شود. نبود mode در snapshot قدیمی همان مسیر native/fallback سابق را حفظ می‌کند.

هزینهٔ همهٔ سه تلاش ناموفق و شاهد کوچک برابر 0.0092602 دلار است و از هزینهٔ کل مهاجرت حذف نمی‌شود. معیار نسخهٔ نهایی به‌صورت صریح «JSON مستقیم و اعتبارسنجی کامل محلی» ثبت می‌شود؛ موفقیت ظاهریِ native یا fallback صفر برای پنهان‌کردن این تغییر گزارش نمی‌شود.

- Runtime: Node 24 و pnpm قفل‌شدهٔ پروژه؛ نصب با `pnpm install --offline --frozen-lockfile`.
- بررسی نهایی: `pnpm verify`، `pnpm build` و `pnpm check:client-bundle` مطابق PROJECT_SPEC.
- ارزیابی واقعی فقط با دستور opt-in، کلید موجود، منابع مصنوعی و بودجهٔ جدا؛ کلید یا محتوای کاربران در خروجی ابزار ثبت نمی‌شود.
- کل داده/تنظیمات تاریخی حفظ می‌شود. rollout باید runهای درحال پردازش با تنظیم قدیمی را لحاظ کند؛ تغییر provider جاری نباید ادامهٔ ناامنِ run قدیمی ایجاد کند.
- انتشار عمومی و تغییر تنظیم ابری به مرحلهٔ نهاییِ نتیجهٔ قابل بازبینی موکول می‌شود؛ مجوز آن از PROJECT_SPEC استنباط نمی‌شود.
- اگر سهمیهٔ هفتگی Codex به ۵٪ باقی‌مانده رسید، توقف در مرز امن، ثبت وضعیت و پرامپت کامل ادامه برای Claude Code الزامی است.
