# Hotfix D59 — متن PR

عنوان و بدنهٔ PR برای `feat/hotfix-d59-audio-start` ← `main`. مدیر سشن‌ها PR را با همین متن باز می‌کند.

## Title

fix(src): accept a confirmed D59 hold without audio seconds

## Body

### Bug

Under D59, a confirmed processing run for audio content already charged in the same allowance period reserves `audio = 0`. `beginTemporaryAudioUpload` (`packages/core/src/src/audio.ts`) refused any hold whose `audio` amount was not positive and threw `validation_failed` (`reservation: confirmed_processing_required`). Every audio upload for such a class failed with HTTP 400 on `POST /api/sources/{id}/audio`, so the run stayed in `awaiting_upload` until the sweep expired it as `audio_upload_rejected` (runs `c8f92d7e` and `fbc79e72`).

### Fix

The start now requires only that the reservation is an open hold of the same learner (`reservationIsOpen`), not a positive audio amount. Nothing else is relaxed:

- Ownership: the source is still read through `getSource` for the learner, and the hold must belong to the learner.
- Run state and reservation identity: the route still calls `validateAudioUploadRun` before the start and before every part and complete action; it requires the learner's run in `awaiting_upload`, the run's own `reservation_id`, and the audio source in the run's input snapshot.
- D29: the temporary upload, verification and deletion path is unchanged.
- Settlement: charged-material accounting already handles a zero audio hold, so the audio is not charged again.

The lapsed-upload reason codes from the full fix (`audio_upload_not_started`, `audio_upload_incomplete`) are not part of this hotfix: `ProcessingView` on `main` only knows `audio_upload_rejected` and `new_confirmation_required`, so new codes would change learner-facing behavior. They ship with the full release.

### Tests

New `packages/core/src/proc/audio-charged-material.int.test.ts` (synthetic data only):

- D59 regression: the same audio processed in a second class of the period goes through start, part upload, confirmation, verification, transcription and publication; the second run's hold has `audio: 0`, the upload is `verified`, the run is `ready`, the lesson cites audio evidence, and consumed audio is unchanged.
- A reservation id that is not an open hold of the learner still refuses the start with `validation_failed`.

Lint, typecheck, `pnpm check:boundaries` and unit tests pass locally; integration and e2e run in CI.

### Migration

None. No schema, flag or UI copy change.

### After deployment

The owner only needs Retry on sessions `572dda3f` and `f36401c8`. The audio is not charged again.
